# Taste
- Communicates in terse imperative commands with minimal context (e.g. "install cloudinary", "implement the todos") and drives implementation in small incremental steps rather than one big request; expects the assistant to execute immediately, inferring scope from prior conversation/IDE context (e.g. "install cloudinary" after requesting frontend work means the frontend package) without asking clarifying questions (e.g. "fix the navbar to show profile photo if avaialble" pasted alongside an IDE context snippet of the selected lines). Confidence: 0.7
- Runtime correctness trumps lint-cleanliness: a lint-driven cleanup that removes an import or symbol that is actually used at runtime (e.g. `motion` used as `<motion.div>` but flagged unused by ESLint) is unacceptable — prefers keeping the code and adding a targeted eslint-disable comment over deleting usage, and expects the fix to be verified with lint+build. Confidence: 0.6
- Reports bugs by pasting the exact runtime error (e.g. "motion is not defined", `net::ERR_CONNECTION_REFUSED`, or `404 (Not Found)` with file/line via IDE context) and expects regressions introduced by earlier edits to be diagnosed and fixed promptly. Confidence: 0.8
- Also reports build/CSS warnings by pasting the exact compiler output (e.g. `@import` ordering warnings with caret markers from a CSS optimization pass) and expects the assistant to trace the root cause and fix it without clarifying questions, then verify the build runs clean. Confidence: 0.5
- Wants background dev servers/processes started for diagnostics to be stopped when no longer needed — responds to the offer to keep one running with terse cleanup commands like "stop it" and expects immediate cleanup without further questions. Confidence: 0.6
- Knows their codebase structure and corrects the assistant's mistaken assumptions with terse factual statements (e.g. "backend already has /api", "dont go through blabber-server the working backend is blabber-backend") — expects the assistant to verify against the actual source, admit the mistake, and redirect investigation/fixes to the authoritative codebase promptly rather than the stale/legacy duplicate. Confidence: 0.6
- Also reports bugs as terse high-level symptom statements without error text (e.g. "on refresh user logs out", "problem is not solved. user is logged out on refresh") and expects the assistant to trace the full stack end-to-end (backend cookie options, CORS, axios interceptors, session-restore bootstrap) to find and fix the root cause rather than asking clarifying questions, including when a previous fix didn't take. Confidence: 0.6
- Communicates feature requirements by pasting reference code snippets (sometimes from a different framework, e.g. a Next.js `getMe` snippet into a Vite SPA) tagged with IDE context (file path + line), and expects the assistant to translate the snippet's intent to the actual stack and flag mismatches (e.g. wrong endpoint name) rather than copying it verbatim. Confidence: 0.6
- For session-restore/auth bootstrap, prefers a dedicated `getMe`-style helper that swallows all errors and returns `null` on any failure (never throws), wired into the auth provider's mount effect to restore the session on refresh. Confidence: 0.5
- Requires all newly designed/created components to live inside their designated component folder (feature-scoped organization) rather than at the project root or arbitrary locations. Confidence: 0.9
- Keeps the CSS clean of build warnings: expects `@import` statements to be ordered correctly (font imports at the top of the stylesheet, before Tailwind/daisyui imports) and a build verification (`npm run build`) to confirm the fix removed the warnings. Confidence: 0.5
- When extending an existing fallback chain (e.g. avatar src), wants all previous fallbacks preserved in order — after a change dropped the final daisyui stock image, corrected with "keep the previous fallbacks too" so the chain stays photo → dicebear → stock image rather than replacing it. Confidence: 0.6
